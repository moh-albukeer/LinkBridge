# سياسة الأمان والخصوصية والصلاحيات ونموذج التهديدات

## 1. إدارة الشهادات ومفاتيح الاقتران (التوليد، التحقق، التجديد، الإبطال)

- **التوليد**: عند أول تشغيل على Windows أو Android، يولّد الجهاز زوج مفاتيح **ECDSA P-256** وشهادة **X.509** موقعة ذاتيًا خاصة بهذا الجهاز فقط (`DeviceIdentity.generate_new`)، ولا توجد أي مفاتيح ثابتة مشتركة في الشيفرة المصدرية.
- **التحقق (Certificate Pinning)**: تُربط هوية الجهاز المقترن ببصمة شهادته **SHA-256** داخل جدول `paired_devices` في قاعدة بيانات SQLite. إذا تغيرت شهادة الجهاز المقابل دون إعادة اقتران صريح، يُرفض الاتصال فورًا.
- **التجديد (Certificate Renewal)**: يوفّر التطبيق زر **«تجديد شهادة الأمان ومفاتيح الجهاز»** (`renew_device_certificate`)، والذي يستبدل المفتاح الخاص والشهادة ويبطل جميع الجلسات النشطة فورًا.
- **الإبطال (Revocation)**: يوفّر التطبيق وظيفة **«إبطال الثقة بالجهاز المقترن»** (`revoke_peer`)، والتي ترسل إشعار `REVOKE_PAIRING` وتلغي صلاحية الجهاز من قاعدة البيانات وتغلق جلسته فورًا.

## 2. صلاحيات Android 9+ ولماذا طُلبت كل صلاحية

يلتزم تطبيق Android بمبدأ **الحد الأدنى من الصلاحيات**:
1. `INTERNET` و`ACCESS_NETWORK_STATE` و`ACCESS_WIFI_STATE`: لفتح مقابس TCP/TLS المحلية عبر شبكة Wi-Fi أو نقطة اتصال الهاتف (لا يتصل التطبيق بأي خادم خارجي).
2. `BLUETOOTH` و`BLUETOOTH_ADMIN` (مقيدة بـ `maxSdkVersion="30"` لأجهزة Android 9..11) و`BLUETOOTH_CONNECT` (لأجهزة Android 12+): للاتصال بالأجهزة المقترنة عبر Bluetooth RFCOMM.
   - **ملاحظة مهمة**: لم نطلب صلاحية الموقع الجغرافي `ACCESS_FINE_LOCATION` لأن التطبيق يعتمد في Bluetooth على قائمة الأجهزة المقترنة في النظام (`bondedDevices`) أو الإدخال اليدوي، مع إضافة `usesPermissionFlags="neverForLocation"` على `BLUETOOTH_SCAN`.
3. **عدم طلب صلاحيات التخزين الواسعة**: لا يطلب التطبيق `READ_EXTERNAL_STORAGE` أو `MANAGE_EXTERNAL_STORAGE`؛ بل يستخدم واجهات **Storage Access Framework (SAF)** الرسمية (`ACTION_OPEN_DOCUMENT` و`ACTION_OPEN_DOCUMENT_TREE`).
4. **عدم استخدام AccessibilityService**: يحترم التطبيق قيود الحافظة في Android ولا يطلب صلاحيات إمكانية الوصول لمراقبة الشاشة أو التطبيقات الأخرى سرًا.

## 3. أماكن حفظ البيانات والنسخ الاحتياطي والحذف

- **على Windows**:
  - قاعدة البيانات والشهادات: `%LOCALAPPDATA%\LinkBridge\linkbridge.db` ومجلد `%LOCALAPPDATA%\LinkBridge\identity\`.
  - مجلد استقبال الملفات الافتراضي: `%LOCALAPPDATA%\LinkBridge\ReceivedFiles\` (قابل للتغيير من الإعدادات).
  - **النسخ الاحتياطي**: يمكن نسخ ملف `linkbridge.db` ومجلد `identity` احتياطيًا.
  - **الحذف والتنظيف**: يوفّر التطبيق أزرارًا داخل الواجهة لمسح سجل الحافظة بالكامل (`clear_clipboard_history`) وتنظيف الملفات المؤقتة `.lbpart` (`cleanup_temporary_files`) دون المساس بملفات المستخدم الأصلية.
- **على Android**:
  - قاعدة البيانات والشهادات: داخل التخزين الخاص المحمي للتطبيق (`context.getDatabasePath("linkbridge_android.db")` و`context.filesDir`).
  - الملفات المؤقتة أثناء النقل: داخل `context.cacheDir` وتُحذف فور التحقق من البصمة أو عند إلغاء النقل.

## 4. نموذج التهديدات والقيود غير المختبرة ميدانيًا (الشفافية الأمنية)

- **ما يحميه التصميم**:
  - التنصت أو التلاعب بالرسائل والملفات على الشبكة المحلية المشتركة أو عبر Bluetooth (بفضل TLS 1.3/1.2 وAES-256-GCM).
  - محاولات الاتصال من أجهزة غير مقترنة على نفس الشبكة أو إعادة إرسال الإطارات المسجلة (Replay Attacks).
  - هجمات اجتياز المسار (Path Traversal) للكتابة خارج مجلد الاستقبال أو استبدال ملفات موجودة.
- **القيود والتهديدات خارج النطاق**:
  - إذا أُصيب جهاز Windows أو Android نفسه ببرمجيات خبيثة تمتلك صلاحيات المستخدم المحلي، يمكنها قراءة الحافظة المحلية أو ملفات المستخدم مباشرة من النظام.
  - ميزة استثناء التطبيقات الحساسة على Windows (`GetClipboardOwner` / `GetForegroundWindow`) هي طبقة دفاع إضافية اختيارية، لكن نظام Windows لا يضمن إرجاع اسم العملية المالكة للحافظة في جميع الحالات، لذا لا يدّعي التطبيق اكتشاف كلمات المرور أو الأسرار تلقائيًا بنسبة 100%.
  - لم تُجرَ اختبارات اختراق خارجية مستقلة أو اختبارات توافق على عتاد راديو Bluetooth فعلي داخل بيئة البناء الحالية (تم اختبار طبقة البروتوكول والتشفير والمقابس برمجيًا بالكامل).
